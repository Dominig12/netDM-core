# ADR-0007. Легаси снимается, а не поддерживается

*Статус:* принято 25.11.2026 по прямому указанию владельца: «многие реализации в обоих билдах являлись легаси, которое можно спокойно устранить; не бойся уничтожать тесты, если в этом есть необходимость; делай так, как будет наилучше всего по документу».

*Контекст:* оба репозитория накопили слой экспериментальных реализаций: shadow-пилоты, сравнительные счётчики, переключатели режимов, заглушки «авторитетности». Документ требует одного авторитетного пути на механику (ARCH-001), отсутствия shadow/fallback на конечной стадии (INT-001) и минимизации нагрузки на BYOND. Поддерживать легаси «на всякий случай» дороже, чем снять его: каждый такой слой считает статистику, которую никто не читает, и создаёт иллюзию переключаемости там, где режим всё равно один.

*Решение:*
1. Легаси-код снимается целиком, а не помечается устаревшим. Комментарий `// legacy` вместо удаления не считается выполнением.
2. Тесты, описывающие снимаемое поведение, удаляются или переписываются под целевое. Покрытие целевого поведения не должно падать.
3. Удаление проверяется тремя каналами: C#-сборка без предупреждений, герметичная DM-сборка без ошибок и предупреждений, живой прогон затронутых тестов в DreamDaemon.
4. Каждое удаление фиксируется в [legacy-removal.md](legacy-removal.md) с причиной, ссылкой на требование и фактическим результатом проверки.
5. Сохраняется то, что нужно целевому поведению: физические локальные пути (INT-002), авторитетные сервисы, инструменты диагностики для разработчиков. Отличие легаси от физической необходимости — явное требование документа, а не удобство.

*Последствия:* решение о снятии принимается по документу, а не по объёму кода. Любой удалённый механизм, который понадобится снова, восстанавливается из истории git, а не из полуживого кода в рабочем дереве.
