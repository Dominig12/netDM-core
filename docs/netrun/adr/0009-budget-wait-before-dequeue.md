# ADR-0009. Резерв полосы планировщика: ждать до изъятия из очереди

*Статус:* принято и выполнено 26.11.2026. Доля полосы включена (`DeliveryBudgetMillisecondsPer100Ms = 25`);
проверки — сборка 0/0, smoke-тесты, два прогона `tests/host-ipc.ps1` подряд `NETDM_IPC_PASS`.

*Контекст:* P8 ([status.md](../status.md) §27) ввёл `WorkBudgetWindow`: доля бюджета окна
зарезервирована за критической и интерактивной работой, чтобы поток фоновых пересчётов
маршрутов не задерживал служебную доставку. Живой прогон показал обратное: с долей 25 мс три
прогона `tests/host-ipc.ps1` подряд упали на разных шагах (таймаут чтения, присутствие,
команда двери), а с долей 0 два прогона подряд прошли.

Причина не в самом правиле, а в месте проверки. `PriorityWorkScheduler.WorkerAsync` забирает
задачу из очереди и только потом ждёт окно в `AwaitWindowBudgetAsync`. Ожидающий воркер держит
слот: когда оба воркера припаркованы на фоновых задачах, интерактивная задача ждёт окна вместе
с ними, хотя её доля не тронута. Чем больше фон, тем хуже доставке — ровно противоположно цели P8.

*Решение:*

1. Пока дефект не исправлен, `DeliveryBudgetMillisecondsPer100Ms` по умолчанию **0**:
   бюджетирование ведёт себя как общий бюджет, живой набор стабилен.
2. Проверка доли переносится **до** изъятия задачи из очереди:
   - выбирается следующий бакет по взвешенному порядку;
   - если его полоса не пускает, проверяются остальные непустые бакеты (интерактивная работа
     может идти, пока фон ждёт);
   - если не пускает ни один — воркер спит до конца окна, не держа задачу.
3. Отказ никогда не возвращает задачу в середину очереди и не теряет её: задача остаётся в
   своём бакете, порядок внутри приоритета сохраняется.
4. Gate возврата доли: `check-all.ps1 -Only host` дважды подряд, плюс живой набор DM. Пока
   оба канала не зелёные дважды — доля остаётся 0.

*Альтернативы:*

- Возвращать задачу в очередь при отказе. Отклонено: очередь `Queue<IWork>` не умеет класть в
  голову, а перестановка порядка внутри приоритета ломает справедливость.
- Увеличивать число воркеров. Отклонено: не устраняет причину, а маскирует её и повышает
  конкуренцию за CPU.
- Оставить долю выключенной навсегда. Отклонено: тогда P8 не решён, а фоновые пересчёты
  по-прежнему могут занять всё окно; правило верное, место проверки — нет.

*Последствия:* исправление не меняет внешних контрактов, но затрагивает горячий путь воркера;
его проверка — только живой прогон, поэтому два зелёных прогона подряд обязательны. До этого
`/api/scheduler` показывает `BudgetWaits*` = 0 — полоса выключена, и это видно, а не
предполагается.
