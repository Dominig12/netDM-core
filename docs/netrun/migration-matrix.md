# Матрица миграции: reuse / adapt / replace / remove / defer

Основание — [t0-audit.md](t0-audit.md). Каждая строка: существующая реализация → решение → обоснование → критерий перехода. Решения по спорным пунктам оформлены отдельными ADR в [adr/](adr/).

Обозначения: **R** — reuse (использовать как есть), **A** — adapt (доработать на месте), **X** — replace (заменить), **D** — remove (удалить), **P** — defer (отложить с записанной причиной).

## 2. Игровой слой SS13 (MOLOT)

| # | Механика | Решение | Обоснование | Критерий/этап |
|---|---|---|---|---|
| G-01 | Двери и кнопки (`door_control_shadow.dm`) | **A** | Команды идут через netDM, дверь исполняет штатной логикой. Нарушения: нет проверки питания/сварки в `netdm_apply_controls`; при выключенном netDM кнопки не работают вовсе (INT-002) | N1: вернуть локальный путь кнопки; N3: NETRUN-действие `door.control` с capability и CU |

| G-05 | Атмос (`atmos_telemetry.dm`) | **A** | Пилот в shadow + рабочие команды `atmos.alarm`. Ценность для игрока появится, когда консоль будет читать сеть | N3: сервис становится источником для консоли |

| G-10 | `netdm_observe.dm` (подсистема) | **A** | Опрос до 10 раз/с, полный ре-экспорт при любом таймауте. Работает, но дорого | N4: объединить частоты, адресный ре-экспорт |
| G-11 | `network_diagnostics.dm` | **A** | `inspect()` — единственный игровой отчёт — недостижим из игры (только тест) | N4: вывести в интерфейс |

## 3. Что переносится в NETRUN как новая функциональность

| # | Возможность | Почему новое, а не адаптация | Этап |
|---|---|---|---|
| N-01 | Цифровые хосты и типизированные компоненты (HOST-001) | В коде таких сущностей нет: узлы графа и эндпойнты — транспортные понятия | N1 |
| N-02 | Виртуальные ресурсы CU/RAM/Storage/Bandwidth с lease (RES-001) | Отсутствуют полностью | N1 |
| N-03 | Capability-модель с fencing и отзывом до commit (SEC-001, SVC-003) | Есть только `AccessScope` | N2 |
| N-04 | Реестр действий + конвейер prepare/reserve/commit (SVC-001, PRIM-001) | Нет общего реестра: команды есть только у сервисов | N2 |
| N-05 | Реестр эффектов с серверными определениями и stacking (PRIM-003) | Нет | N2 |
| N-06 | Боковой интерфейс NETRUN с вкладками и картой трафика (UI-001/002/003) | Одно окно без вкладок | N4 |
| N-07 | Безопасность: Breach, наблюдение, ICE (SEC, §9) | Нет | N6 |
| N-08 | Программы: общий IR, bounded VM, конструктор (SCRIPT-001/002) | Есть только текстовый shell | N5 |
| N-09 | Внешний мир и генерация локаций (§14) | Нет | N7 |

## 5. Отложено (defer) с записанной причиной

| Что | Причина | Условие возврата |
|---|---|---|
| Шардирование владения NETRUN по доменам | ARCH-003 разрешает только по измерениям; сейчас один логический владелец укладывается в бюджет | Профиль Full Station покажет насыщение единственного writer'а |
| Полное Event Sourcing и БД цифрового состояния | §18.2 требует определить, что переживает падение, но не требует ES | После появления цифровых личностей, которые нужно восстанавливать |
| Сложная аппроксимация фоновых локаций | §14.3: для первого релиза предпочтителен небольшой мир без аппроксимации | После первого внешнего среза |
| Перенос consciousness/mind, embodiment боргов | Требует согласования с правилами ролей (TBD §21.3) | Решение владельца |
| Реальный DSL с компилятором | §11.2: на первом этапе достаточно IR последовательностей | После плейтеста V3/V4 |
