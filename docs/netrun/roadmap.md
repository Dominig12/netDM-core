# План работ и порядок этапов

Порядок задан §19 спецификации; нумерация `N*` — наши этапы, потому что часть `T*` уже выполнена существующим кодом. Правило: этап считается завершённым, только когда его gate проверен и результат записан в [status.md](status.md).

| Этап | Зависит от | Что появляется | Gate |
|---|---|---|---|
| **N0. T0-аудит** | — | [t0-audit.md](t0-audit.md), [migration-matrix.md](migration-matrix.md), [architecture.md](architecture.md), ADR-0001…0006, baseline сборки и тестов | Воспроизводимые команды, фактические результаты, список непроверенного |
| **N1. Домен NETRUN** | N0 | `NetRun.Core`: хосты и компоненты, виртуальные ресурсы, capability-модель с fencing, реестр действий и конвейер, реестр эффектов; харнесс `tests/NetRun.Tests` | RES-001, SEC-001, SVC-001/003, PRIM-003, HOST-001 покрыты тестами; сборка без предупреждений |
| **N2. Интеграция с Host** | N1 | `NetRun.HostService` в composition root: домен живёт в процессе Host, тикает по игровому времени, принимает `netrun_*` control-plane операции через `IHostIpcModule`, отдаёт проекцию для UI | `tests/host-ipc.ps1` проверяет регистрацию хоста, выдачу права, выполнение действия, отказ и отзыв права на живом Host |
| **N3. Первый сквозной сервис** | N2 | Доменное действие `door.control` доводится до штатного обработчика двери через `machine.door` над NETDM; игровые контракты выносятся в `NetRun.Content` через `IServiceContractModule`; закрывается обход леджера в техуэбе | AT-05, AT-06, AT-08, AT-09, AT-11, AT-29 на живом Host; DM-мир компилируется |
| **N4. Клиент и карта** | N2 | Боковые вкладки UI-001, независимые состояния UI-002, слои и реальный трафик UI-003; фильтрация проекций по знанию; снятие погружения в `Shutdown` | UI-001…003; проверка отсутствия утечки скрытого состояния (AT-12); TGUI собирается |
| **N5. Программы** | N3, N4 | Общий IR последовательностей и правил, bounded VM с квантом, бюджетами и `await`; конструктор без кода | AT-15, AT-16, AT-17, AT-18, AT-19 |
| **N6. Безопасность и агенты** | N3, N4 | Breach как игровая операция, наблюдение и знание, ICE, простой вирус, готовые пресеты и правила поведения | AT-07, AT-13, AT-14, AT-22; плейтест конфликта |
| **N7. Внешний мир** | N2, N6 | Второй сектор через relay, виртуальные локации, генерация по seed, автономные события | AT-03, AT-04, AT-33; изоляция и возврат состояния |
| **N8. Цифровая жизнь** | N4, N6, N7 | Гост-роль цифровой личности, ядро и присутствие, миграция с fencing, снимки и восстановление | AT-23, AT-24, AT-25, AT-26 |
| **N9. Остальные миграции** | N3 | КПК, telecomms, камеры, атмосфера, карго, медицина по матрице §16 | Для каждой миграции свои тесты и удалённый bypass |

Правила порядка:

1. Каждый этап заканчивается работающей функцией, а не интерфейсом. Заглушка допустима только как временная мера с записанным в [status.md](status.md) условием замены.
2. Этапы N4 и N5 могут идти параллельно N3 при стабильных контрактах.
3. Функции MAY и поздние расширения не блокируют ранний срез.
4. Тяжёлые проверки (живой мир, нагрузка) не запускаются после каждого изменения: быстрые — на каждом этапе, тяжёлые — по этапам.
